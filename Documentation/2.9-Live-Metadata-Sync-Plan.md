# Metadata sharing targets

## 2.8.1 — Repeat imports

Metadata-only imports merge clips and photographers by UUID. Incoming matching records and programming settings win; omitted clips, photographers, and day tracks remain. Validate the combined schedule before persisting any changes. Jobs-and-metadata packages retain their existing new-job import behaviour.

Selected-day exports include complete clips touching the selected days, preserving overnight durations and UUIDs. Older exports remain readable, but any truncation or randomly assigned fragment IDs already present in those files cannot be reconstructed; re-export with 2.8.1 for stable partial-day sharing. Deletion propagation and conflict history are deferred.

## 2.9.0 — Live sync target

- Start with one editor publishing a shared programming file and other users automatically receiving updates through iCloud Drive or Dropbox.
- Give shared programmings identities independent of local sync jobs; keep credentials and local folder access outside the shared data.
- Monitor provider-delivered changes, coordinate file access, validate updates, and expose offline, pending, failed, and last-synced states.
- Define revisions and deletion records before enabling multiple editors.
- Merge independent edits; preserve competing versions and ask users to resolve conflicting edits to the same clip.
- Test offline edits, delayed and out-of-order delivery, simultaneous edits, provider conflict copies, deletion propagation, and recovery.

Shared-file delivery is eventual; immediate delivery is not guaranteed. Multiple-editor support needs an explicit design decision after the one-editor workflow is validated.
