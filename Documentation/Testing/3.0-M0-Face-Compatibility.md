## Existing exporter and required companion change

`Models/KnownPerson.swift` defines a v1.0 `KnownPeopleManifest` with OS, creation date, optional exporter, people count and embedding count. It has no embedding-space, model, preprocessing, vector encoding, library ID or revision. Several comments still describe legacy Vision feature prints although the executed codec path is AuraFace.

`KnownPeopleArchiveService.export` in `Services/KnownPeopleService.swift:520` serializes this manifest, `people.json` (array of Codable `KnownPerson`; embedded `Data` is JSON base64), `thumbnails/<personUUID>.jpg`, and `embedding_thumbnails/<embeddingUUID>.jpg`. It uses default JSON date encoding (seconds from Apple's reference date) and `ditto -c -k --keepParent`, adding one temporary UUID wrapper directory. Import at line 598 extracts with ditto, locates root or one wrapper's `people.json`, and does not consult the manifest. `KnownPeopleService.importFromZip` at line 2926 adds unseen UUIDs only. Neither this archive admission nor its merge semantics satisfies FTP Sync snapshot replacement requirements.

Proposed minimal interchange v2 (not yet agreed or implemented):

- Root `manifest.json`, `people.json`, optional JPEG thumbnail directories as above; optionally accept exactly one declared wrapper for compatibility. Require a format ID and integer schema revision 2. Unknown/missing revision fails before mutation.
- Manifest includes persistent `libraryID` UUID, revision digest, UTC export time, exporter app/version/source revision, exact people/embedding counts, embedding-space version 3, component ID `auraface-r100-coreml`, model ID `AuraFace-v1/glintr100`, preprocessing revision `photo-agent-eyes112-rgb-v3`, vector encoding `fem2-float32-le`, dimension 512 and L2-normalized flag. The preprocessing string is a proposed stable identifier for the pinned behavior above; any semantic change requires a new identity.
- The manifest binds SHA-256 and byte length for every payload file. Compute library revision from canonical ordered file declarations plus processing contract; exclude volatile export timestamp so identical snapshots stay identical. Preserve the library ID across renames/removals and future exports.
- Reuse the present person and embedding UUID fields and names. Document date encoding explicitly if preserving current JSON. Permit absence of reference thumbnails; no source image paths, notes or descriptions are required for FTP Sync. Names are literal data.
- Validate ZIP entries before extraction: reject absolute/traversal paths, symlinks, duplicate/case-colliding paths, unexpected files, count/size expansion overflow, and corrupt/oversized images. Validate unique person and embedding IDs, manifest counts, declared hashes, codec magic/length, exactly 512 finite values, and a documented nonzero normalized-vector tolerance. Set measured finite archive/library limits before implementation.
- Stage all validation into app-owned storage, then atomically switch the active snapshot. A failed or cancelled import leaves the old snapshot active. Existing operations hold their prior library/model snapshot. Replacement incorporates renamed/removed people. No implicit merge and no reading Photo Agent's live library.
- Legacy v1 cannot demonstrate space/preprocessing compatibility from its manifest. Reject with compatible-re-export instructions unless a separately reviewed migration proves the exact origin; never reinterpret legacy Vision blobs or reset existing data.

Companion integration gate: prepare exporter patch/tests in isolation; coordinate with Photo Agent's active coordinator, pin its integrated commit, and prove export → FTP Sync import → rename/remove → replacement using disposable synthetic identities. Contract proposal alone does not close M0/M4.
