# Aagedal FTP Sync delivery-latency benchmark

Harness smoke verification only. App source `adf995b` with benchmark-storage/logging
isolation changes; production mapping behavior was still unchanged in this run.
One measured sample does not estimate a statistical p95 or establish M0 budgets.
Other app/tasks were active on the host. The separate full-fixture run is required.

Recorded 2026-09-09 23:07:44 CEST on `macOS-27.0-arm64-arm-64bit-Mach-O; arm64; Model Name: MacBook Pro; Chip: Apple M5 Pro; Memory: 64 GB` with `Xcode 26.6 / Build version 17F113` using the Debug configuration.

## Fixture and method

- Loopback FTP and SFTP services exposed the same fixed tree: 10 top-level directories × 10 subdirectories × 10 zero-byte files (1,000 files; 111 directories including the root).
- Service fixture versions: pyftpdlib 2.2.0, paramiko 5.0.0.
- One JPEG had a current modification date and all other files used 2000-01-01. The sync job's one-hour recent-file filter therefore published exactly one file.
- Each cell used one unrecorded warm-up and 1 measured iterations. Cold means a new protocol connection for each iteration; warm means a reused authenticated connection. Both states benefit from the host filesystem cache after warm-up.
- Full scan measures `EndpointSession.listFiles()`. First publication is timestamped when the destination accepts the newest file; the benchmark still lets the authoritative full scan and reconciliation finish before starting another sample.
- The historical comparison baseline was recorded on September 1, 2026 before completed-directory publication was implemented, using 100,000 files and five measured samples. Comparisons are shown only for matching fixture parameters.
