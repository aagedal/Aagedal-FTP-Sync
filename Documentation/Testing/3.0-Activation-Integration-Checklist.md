# Activation integration after guarded persistence

Updated for the per-image integration checkpoint, 2026-09-11. These are implementation requirements,
not completed acceptance criteria. Storage schema 3, template language 1, package 3
and proposed calendar protocol 3 are distinct. Current sharing still uses protocol 2.

## Implemented guard checkpoint

Strict `templateVersions` (headline/description/keywords → 1) and
`copyrightTemplateVersion` (1) now preserve absence-as-literal and reject malformed
markers/sources. Validated mutators replace pairs together; encoding rejects invalid
active drafts. Keywords activation covers the complete ordered source list. Presets,
shared copies and atomic merge decisions preserve pairs.

Legacy stores reject recognized markers; compatible versioned stores retain strict
active records. Unsupported active state cannot fall back or be overwritten through
stale saves. Configurations scan selected content to choose version3, keep literal
selections at2, preflight plain/decrypted headers and reject marker/version mismatches.
The old decoder fixture is unit evidence only, not actual old-client execution.

Protocol2 outbound/inbound, cached snapshots, pending receipts and linked jobs reject
activation before credentials/network or application; stale saves retain incompatible
cache bytes. Pure detached local copies/merges can preserve activation.

Preview, transfer and reprocessing now use shared per-image preparation for active
assignments, with a persisted zone and frozen operation date. Literal writer overloads
still reject accidental activation. Per-field audit evidence and incomplete-result
source retention are integrated. Active reprocessing compares immutable originals
before local publication; no proposed fields means no writer invocation.
Standalone photographer lists remain v1 literal-only; active Copyright uses package3.
See `2026-09-11-M1-Per-Image-Resolution.md` for evidence and remaining limits.

## Next production slice

1. Exercise frozen context, strict original capture/fallback and field preservation in
   the actual app. Synthetic RAW dispatch tests are not real-camera RAW evidence.
2. Verify cancellation and proposed-value/omission details in the actual preview UI.
   Independent preview/reprocess operations intentionally receive different dates;
   the UI must not imply preview reservations or a committed write.
3. Test recovery directories and concurrent reprocess edits through the real app.
   Exclusive renames are not crash-atomic group publication or isolation from open
   external writer file descriptors. Preserve incomplete-result source retention.
4. Wire validated source/version mutators into clip/preset/Copyright editors with
   Insert Variable, asynchronous cancellable preview, keyboard access and help.
   Existing public raw setters can still form invalid in-memory drafts; do not claim
   the old editor bindings themselves are atomic activation editors.
5. Integrate geocoder context/settings independently of calendar/clip enablement.
   Align existing-sidecar/no-GPS RAW writer behavior with effective coordinates before
   using geocoded values. Keep unavailable person/location dependencies explicit.

## Sharing still required

Implement the proposed protocol3 namespace and server capability enforcement before
lifting protocol2 activation rejection. Actual older clients must never receive or
upload downgraded active documents, including cached/offline cases. Preserve legacy
calendar sharing. Add explicit detached-copy recovery UX for incompatible cached state.
No server deployment is authorized by the implementation automation.
