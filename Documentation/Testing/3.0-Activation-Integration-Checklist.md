# Activation integration work remaining after bootstrap

Read-only audit at app-code `14e2e1f`, 2026-09-10. These are implementation
requirements, not completed acceptance criteria. Storage schema 3, template language 1,
configuration package 3 and the proposed calendar protocol 3 are distinct versions.
The current client expects calendar protocol 2 (with explicit protocol-1 handling).

## Atomic persisted values and execution

The pure MetadataTemplates package already models source and activation together.
The app's ScheduledMetadataFields and PhotographerProfile do not yet persist markers.
Use the proposed wire names `templateVersions` (headline/description/keywords → 1)
and `copyrightTemplateVersion` (1), with absence retaining literal behavior. Reject
null, malformed, unknown and future marker values; never infer activation from braces
or an enclosing file version. Keywords activation covers the entire ordered source list.
Validate an edit before replacing its source/version pair.

Both transfer and reprocessing currently call `MetadataProcessingCoordinator.prepareLiteral`.
Before accepting activated persisted values, either integrate those calls with the same
frozen activated context or explicitly refuse activated assignments before writing.
Merely adding Codable fields would let literal paths publish raw template source.
Legacy store saves must reject unsupported active semantics until the v3 runtime owns them.

## Copies and merges

- SharedMetadataDocument reconstructs photographer records and must preserve Copyright
  activation deliberately.
- Merge each source/version pair atomically, including the whole Keywords source list;
  independent scalar merges can combine one author's source with another's activation.
- MetadataPreset normalization must preserve active keyword source bytes until expansion.
- Preserve pairs through selected-day transfer, profile refresh, preset application,
  schedule copies and both sides of pending receive receipts.

## Configuration packages

Choose payload version 3 only after scanning the actual selected portable contents:
programming, presets and photographer library. Jobs-only exports deliberately exclude
metadata. Literal-only selections may keep the exact v2 shape with new keys omitted.
Reject recognized markers mislabeled as v1/v2; do not activate or strip them silently.
Probe the inner format/version before domain decoding for both plain and decrypted
payloads. The encryption envelope can remain version 1. Imports remain disabled and
must not carry private model/library files or local bindings as portable content.

## Calendar gate

Until protocol-3 capability enforcement is implemented, prevent activated documents
from entering legacy-bound calendars. Fence outbound actions before credentials/network,
as well as incoming, cached, merge and apply paths. A guard on putCalendar alone cannot
protect automatic get/merge/apply. Full compatibility needs server enforcement and the
proposed separate protocol-3 namespace; a client flag alone does not protect older peers.
Local activation can require an explicitly detached/new local copy until sharing is ready.

## Required regression cases

Literal braces unchanged; malformed/future markers rejected; invalid edits retain the
previous pair; exact active keyword source survives normalization/copies; active plain
and encrypted packages round-trip with version 3; an actual old decoder rejects them;
v1/v2 marker mismatch is rejected; pair merge conflicts remain explicit; no transport for
active legacy-bound calendars; unsupported active assignments never reach metadata writers.
These tests supplement the full plan and do not replace actual UI or old-client evidence.
