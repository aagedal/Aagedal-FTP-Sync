# Aagedal FTP Sync 2.5 Metadata Roadmap

## Goal

Automatically apply editorial metadata to incoming images on a per-job basis. A filename prefix identifies the photographer, while a scheduled clip selects the event metadata that is valid at the file's timestamp.

## Phase 1 — Safe end-to-end foundation

Status: implemented in the initial 2.5 work.

- Store photographer profiles and metadata schedules inside each sync job.
- Match prefixes case-insensitively against the filename, independent of folders and extensions.
- Use half-open clip ranges (`start <= timestamp < end`) so adjacent clips have an unambiguous boundary.
- Apply non-empty Headline, Description, Keywords, Creator, and Copyright values through SwiftExif during transfers to a local destination, preserving fields that were left blank in the programming UI.
- Synchronize IPTC values into XMP.
- Preserve the source modification time and avoid retransferring files solely because embedded metadata changed their size.
- Add validation for duplicate prefixes, orphaned clips, invalid ranges, and overlapping clips on one photographer track.
- Provide a separate programming window reachable from both job settings and the menu-bar window.
- Provide a calendar, persistent photographer library, visual day tracks, clip editing, cross-day confirmation, and copying to another photographer.

## Phase 2 — Direct timeline editing

Status: implemented.

- Drag clips along the timeline and snap to configurable intervals.
- Resize either edge, with explicit confirmation when a resize crosses midnight.
- Add multi-select and copy/paste across several photographer tracks.
- Highlight schedule gaps, overlaps, the current time, and clips that continue from another day.
- Add keyboard navigation and shortcuts for fast newsroom programming.

## Phase 3 — Metadata policies and RAW workflow

- Let each job choose whether scheduling uses source modification time, local arrival time, or camera capture time from Exif.
- Let each field overwrite, preserve, append, or clear existing metadata.
- Add XMP-sidecar output for proprietary TIFF-based RAW formats that SwiftExif deliberately refuses to rewrite in place.
- Decide whether CR3 and DNG should embed metadata, write sidecars, or follow a per-format job policy.
- Add an explicit “reprocess existing local files” action when programming changes after files have arrived.

## Phase 4 — Operations and confidence

- Report metadata-applied, skipped, and failed counts separately from transfer counts.
- Keep a per-file audit trail containing the matched photographer, clip, timestamp policy, and SwiftExif warnings.
- Persist the original source signature so size verification can still detect an unusual source change that keeps the same modification timestamp after metadata has changed the destination size.
- Add dry-run preview for a local folder before enabling automation.
- Add fixtures and round-trip tests for JPEG, TIFF, DNG, CR3, HEIC, and XMP sidecars.
- Add recovery behavior for partial failures so a metadata error cannot leave a damaged destination file.

## Product decisions to confirm

1. Which timestamp should be the default: source modification time, local arrival time, or Exif capture time?
2. Should programmed values always overwrite existing Headline/Description/Keywords, or should that be configurable per field?
3. For RAW files, should sidecars be the universal default, or should writable formats such as DNG and CR3 embed metadata?
4. Should clips contain their own metadata values, or reference a reusable preset library shared across jobs and days?
5. When programming changes, should matching files already present locally be reprocessed automatically or only on demand?
