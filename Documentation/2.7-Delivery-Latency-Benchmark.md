# Aagedal FTP Sync 2.7 delivery-latency benchmark

Recorded 2026-09-01 21:03:18 CEST on `macOS-27.0-arm64-arm-64bit-Mach-O; arm64; Model Name: MacBook Pro; Chip: Apple M5 Pro; Memory: 64 GB` with `Xcode 26.6 / Build version 17F113` using the Debug configuration.

## Fixture and method

- Loopback FTP and SFTP services exposed the same fixed tree: 100 top-level directories × 10 subdirectories × 100 zero-byte files (100,000 files; 1,101 directories including the root).
- Service fixture versions: pyftpdlib 2.2.0, paramiko 5.0.0.
- One JPEG had a current modification date and all other files used 2000-01-01. The sync job's one-hour recent-file filter therefore published exactly one file.
- Each cell used one unrecorded warm-up and 5 measured iterations. Cold means a new protocol connection for each iteration; warm means a reused authenticated connection. Both states benefit from the host filesystem cache after warm-up.
- Full scan measures `EndpointSession.listFiles()`. First publication measures a complete `SyncEngine.run`, ending after the newest file was downloaded and accepted by the destination.
- The current engine waits for the authoritative full listing before publication. These numbers are a 2.7 baseline, not a measurement of the completed-directory design.
