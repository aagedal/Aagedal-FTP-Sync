## Release-tier gap estimate

The plan defines final acceptance, not a separate beta gate. For a 3.0 beta that
exercises the declared feature scope, five substantial groups remain: (1) production
face-model trust, hosted signed artifacts and installer verification; (2) authorized
real-face calibration plus the companion export/import lifecycle; (3) native activated
variable/geocoding/recognition preview, transfer and reprocessing with real embedded
images and RAW/XMP integrity; (4) actual protocol-3 calendar migration and older-
client/server behavior; and (5) a 3.0 versioned signed beta build with candidate-source
core regressions and macOS 14 smoke. The PHP/MariaDB suite is now passing; it does not
replace group 4's native integration. None of these five groups has complete acceptance
evidence yet. The app remains a 2.9.2 development build.

The new programming-derived server filename mode now passes a live FTP/FTPS/SFTP
day-change, empty-day and RAW/XMP companion case with synthetic bytes. A separate
generated decodable JPEG and valid XMP sidecar now pass activated processing on
all three transports; camera RAW, native UI and external-reader acceptance still
belong to group 3.

Final release additionally needs the complete M5 delivery/idempotence/rollback matrix,
controlled cold/warm enriched performance against M0 budgets, oldest/newest supported
macOS and native VoiceOver/localization evidence, the 41 required agent checklist cases
plus independent review, and M6 documentation/notices/versioned signed archive and the
user-only final manual case. The current development binary has no agent or user
checklist results. Rough elapsed engineering time, assuming production model artifacts,
authorized labeled fixtures and a macOS 14 test host are available, is 2–4 weeks to a
meaningful beta and 4–8 weeks total to a final user-test handoff. These are planning
ranges, not a release date; unavailable prerequisites can extend them.
